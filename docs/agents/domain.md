# Domain docs

This repository uses a single context: root `GLOSSARY.md` for vocabulary and `docs/adr/` for architectural decisions.

When exploring a domain, read the glossary and relevant ADRs if present. Use the glossary’s terms in issues, proposals, and tests; surface conflicts with an existing ADR explicitly.

These documents are created lazily by `/domain-modeling`, including through `/grill-with-docs`, when terms or decisions are resolved. Missing files require no setup.
